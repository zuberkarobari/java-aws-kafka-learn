Actuator & Observability

Production-grade Spring Boot apps aren't just functional — they're observable. Master Actuator endpoints, custom health indicators, Micrometer metrics, and Prometheus/Grafana integration — the pillars of modern DevOps.

1. Definition

Simple English

Actuator is the cockpit dashboard of your Spring Boot app. Instead of guessing if your app is healthy, you have real-time readouts: "Is the database connected? How many requests per second? What's the memory usage?" — all exposed as HTTP endpoints.

Technical

Spring Boot Actuator exposes production-ready endpoints for monitoring and management. Combined with Micrometer (Spring Boot's metrics facade), it collects dimensional metrics (counters, gauges, timers) and exports them to monitoring backends like Prometheus, Datadog, or Cloudwatch.

Purpose

Powers Kubernetes liveness/readiness probes, enables SRE dashboards, drives auto-scaling decisions, and provides audit trails. Without observability, debugging production incidents is like flying blind.

3. Real-World Project Example

Kubernetes Monitoring Stack

Spring Boot → Actuator → Prometheus → Grafana — the full production observability pipeline.

Liveness & Readiness Probes

Kubernetes calls /actuator/health/liveness every 10s. If it returns DOWN, k8s restarts the pod. /actuator/health/readiness determines if traffic should be routed — Spring automatically marks the pod not-ready during startup or DB reconnection, preventing requests to broken instances.

Prometheus Scraping

Prometheus scrapes /actuator/prometheus every 15s. Metrics include: http_server_requests_seconds (p95 latency), jvm_memory_used_bytes, hikaricp_connections_active (DB pool exhaustion alerts), and custom business metrics.

Custom Business Metrics

A Micrometer Counter increments on every failed payment. A Grafana alert fires when payment.failures.total exceeds 10 per minute. The on-call engineer is paged before the user-facing error rate becomes visible in monitoring.

4. 7 Key Points For senior-level depth

1

Secure Actuator Endpoints

Expose only /health and /info publicly. Secure or disable /env, /beans, /shutdown. Best practice: expose sensitive endpoints on a different port (e.g., 8081, management port) protected by network policies — never expose them on the public-facing API port.

2

Custom HealthIndicator

Implement HealthIndicator to add custom health checks — e.g., checking if an external payment gateway is reachable, or if a required Kafka topic exists. Spring aggregates all HealthIndicator results into the /actuator/health response automatically.

3

Micrometer — 4 Core Metric Types

Counter: monotonically increasing (total requests, errors). Gauge: current value that can go up/down (active connections, queue size). Timer: measures duration + count (HTTP request latency with percentiles). DistributionSummary: distribution of events (payload sizes).

4

Liveness vs Readiness

Liveness: "Is the process alive?" — if DOWN, restart the pod. Only fail if the app is in an unrecoverable state (deadlock). Readiness: "Is the app ready to receive traffic?" — if DOWN, remove from load balancer. Fail during startup, DB connection loss, or heavy GC pauses.

5

Micrometer vs Prometheus

Micrometer is the metrics collection library (the "SLF4J of metrics"). Prometheus is a time-series database and monitoring system. You write Micrometer code once and swap backends: add micrometer-registry-prometheus for Prometheus, micrometer-registry-datadog for Datadog — same code, different export target.

6

Distributed Tracing (Micrometer Tracing)

Spring Boot 3 integrates Micrometer Tracing (replacing Spring Cloud Sleuth). Add micrometer-tracing-bridge-otel and an exporter (Zipkin or Jaeger) to auto-propagate traceId/spanId across HTTP calls and Kafka messages — enabling end-to-end request tracing in microservices.

7

Runtime Log Level Changes

The /actuator/loggers endpoint lets you change log levels at runtime without restarting. POST to /actuator/loggers/com.example.payments with body {"configuredLevel": "DEBUG"} to enable debug logging for a specific package during a live incident — then switch back to WARN when done. No deployment needed.

# application.yml — Actuator + Prometheus config
management:
  server:
    port: 8081           # Separate port for management
  endpoints:
    web:
      exposure:
        include: health, info, prometheus, loggers, metrics
  endpoint:
    health:
      show-details: when-authorized
      probes:
        enabled: true          # Enables /health/liveness + /health/readiness
  metrics:
    distribution:
      percentiles-histogram:
        http.server.requests: true  # p50, p95, p99 histograms

/* 1. Custom HealthIndicator — checks external payment gateway */
@Component
public class PaymentGatewayHealthIndicator implements HealthIndicator {

    @Override
    public Health health() {
        try {
            HttpResponse response = pingStripeApi();
            if (response.statusCode() == 200) {
                return Health.up()
                    .withDetail("gateway", "Stripe")
                    .withDetail("latencyMs", response.elapsed())
                    .build();
            }
            return Health.down().withDetail("status", response.statusCode()).build();
        } catch (Exception e) {
            return Health.down().withException(e).build();
        }
    }
}

/* 2. Custom business metrics with Micrometer */
@Service
public class PaymentService {

    private final Counter paymentSuccessCounter;
    private final Counter paymentFailureCounter;
    private final Timer paymentTimer;

    public PaymentService(MeterRegistry registry) {
        this.paymentSuccessCounter = Counter.builder("payment.success.total")
            .description("Total successful payments")
            .register(registry);
        this.paymentFailureCounter = Counter.builder("payment.failure.total")
            .tag("reason", "gateway_error")
            .register(registry);
        this.paymentTimer = Timer.builder("payment.processing.duration")
            .publishPercentiles(0.5, 0.95, 0.99)
            .register(registry);
    }

    public PaymentResult charge(ChargeRequest req) {
        return paymentTimer.record(() -> {
            try {
                PaymentResult result = gateway.charge(req);
                paymentSuccessCounter.increment();
                return result;
            } catch (Exception e) {
                paymentFailureCounter.increment();
                throw e;
            }
        });
    }
}

7. Senior Developer Answer

"Our observability stack is Spring Actuator → Micrometer → Prometheus → Grafana. Actuator is the foundation — I enable liveness and readiness probes for Kubernetes, with the critical distinction that liveness only fails for true unrecoverable states (deadlocks, OOM), while readiness handles transient issues like DB reconnection.

For custom metrics, I use Micrometer because it's backend-agnostic. I write Counter and Timer code once, and we can export to Prometheus today, Datadog tomorrow, by swapping the registry dependency. I always add tags (dimensions) to metrics — for example, tagging payment metrics by currency or region — so we can slice dashboards by any dimension in Grafana.

Security is critical: actuator endpoints run on a separate management port (8081), blocked by network policy from the internet. Only Prometheus can scrape that port. The /actuator/env endpoint is disabled entirely — it could expose secrets. The only endpoints on the public port (8080) are none — all management traffic is internal."
